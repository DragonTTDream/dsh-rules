# 这几条规则，我记不清是哪一次错逼出来的

下面 5 条规则在正常使用、正常生效，只是**没有一次具体的事故记录**挂在它们下面。
它的依据目前是"我判断需要"，而不是"曾经踩过一次"。

**这不需要你做任何事。** 它的唯一作用是：将来某天真发生了一次，把案例写成
`INC-<日期>-<短名>.md`，再把那条规则的 `evidence:` 指过去就行。
想不起来源就让它一直躺着——**不要编一个案例来充数**（编造本身违反 R-01）。

| 规则 | 缺什么 | 怎么找 |
|---|---|---|
| R-02 先出方案再动手 | 一次"没出方案就动手导致返工"的具体案例 | 翻返工过的会话，找第一次返工的时间点 |
| R-04 信息缺口说清楚 | 一次"用假设填缺口"的具体案例 | 找用户事后说"我没说过这个"的记录 |
| R-09 产物按领域归位 | 一次"产物放错地方"的具体案例 | 找用户说"你怎么写这来了"的记录 |
| R-10 建移删留台账 | 一次"清理时删错了"的具体案例 | 找收尾清理后要恢复文件的记录 |
| R-15 委派三交代 | 一次"派活没写判据、交回一堆材料"的案例 | 翻子代理任务与它的产出 |
