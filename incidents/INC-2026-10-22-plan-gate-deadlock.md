# 事故：计划门自锁

## 现象

2026-10-22 11:49，一次已获批准的文件写入被拒：

```
方案还没定稿（~/.dsh/plans/active.md 里 status: draft）⇒ 禁止改盘
```

但**本会话从未创建过计划文件**。更糟的是：**修复这个缺陷的写操作也被同一缺陷拦住**，
形成鸡生蛋死锁——`cp`、`python -c "...write..."`、`git commit` 全部被拒。

## 级联路径

`全局单文件计划` → `批准判定缺 approved_at` → `守卫禁一切改盘` → **修守卫的写操作也被拦**（自锁）

## 根因（三件事叠加）

1. **计划文件是全局单文件** `~/.dsh/plans/active.md`，不带会话归属。
   别的任务（批次 `b-alert-v2c`）留下的文件，会把**所有会话**都当成"方案未定稿"。
2. **批准判定过严**：`status: approved` 之外还要求 `approved_at`；那份文件只有
   `approved_msg` 没有 `approved_at` ⇒ 被判成 draft。规则本身合理（自批不算批），
   但配合全局单文件就变成全局卡死。
3. **命令粒度粗**：守卫对 bash 用**命令文本正则**匹配 `rm|mv|cp|git commit|…`。
   于是"在 python 里写一段包含 `rm` 字样的测试代码"也被判成改盘——
   连改代码修缺陷都做不到。

## 处置

- 把遗留计划**归档**（未删除）：`~/.dsh/plans/active.md` → `~/.dsh/plans/archive/active-<时间>-b-alert-v2c.md`
- `planGate` 改为**按会话隔离**：计划声明 `session:` 且不等于当前会话 ⇒ 不归我管；
  没有 `session` 字段的历史文件 ⇒ 不拦任何人
- 新增用例：`别的会话的 draft ⇒ 不拦本会话`（负样本）

## 教训

- **守卫的自锁比它要防的错更贵**：任何"禁止改盘"的机制，都必须留一条
  "改它自己"的通道，或保证触发条件不会跨会话命中。
- **全局单文件 + 严格判定 = 全局死锁**。状态要么带归属，要么允许"无归属即忽略"。
- 粗粒度文本匹配会误伤：判定"是否改盘"应看**工具语义**（write/edit/命令首词），
  而不是整条命令里出现过什么字符串。

## 可复用判据

出现「明明没有 draft 却被拦」时，按顺序查：

1. `~/.dsh/plans/active.md` 存在吗？内容是当前任务吗？
2. 有 `session:` 字段吗？和当前会话一致吗？
3. 被拒的命令文本里，有没有只是**碰巧包含** `rm`/`cp`/`git commit` 这些词？

## 带走什么

- 可复用判据（已进经验库）：「明明没有 draft 却被拦」⇒ 查计划文件归属与 `session:` 字段
- 已下沉机制：`planGate` 按会话隔离 + 跨会话负样本用例 `test/plan-gate.mjs`
