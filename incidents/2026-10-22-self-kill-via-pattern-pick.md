# 2026-10-22 用命令行模式挑进程，把本次调用链一起杀了

## 现象

执行 `pgrep -f "windowB2a.sh"` 系命令清理窗口进程时，**匹配到了这条命令自己的命令行**，
于是把本次 bash 调用的进程链（PID 3093118 / 3093675 / 3093682）一起 SIGTERM，命令被信号终止。
用户原话：「上述内容以前都会被直接拦截的，怎么现在不拦截了，保护不了了起不了作用了」。

## 取证

用守卫把九种写法逐个喂进去（探测脚本走文件，避免守卫对命令文本做内容无关匹配）：

| 写法 | 旧判据 |
|---|---|
| `pkill -f <模式>` | 拒 ✅ |
| `pgrep -f <模式> \| xargs kill` | 拒 ✅ |
| `pgrep -f <模式>` 配 `until` 循环 | 拒 ✅ |
| `kill $(pgrep -f <模式>)` | **放行** ❌ |
| `pgrep -f <模式> \| while read p; do kill "$p"; done` | **放行** ❌ |
| `kill -TERM $(pgrep -f <模式> \| tr …)` | **放行** ❌ |
| `ps -eo pid,cmd \| grep <模式> \| awk … \| xargs kill` | **放行** ❌ |
| `pgrep -f <模式>`（只读） | 放行（正确） |
| 带 `ps -o comm=` 白名单 | 放行（正确） |

## 根因

**判据是形态枚举，不是判据。** 旧规则只覆盖了三种字面写法；
危险的是「用命令行模式挑进程直接杀」这**一类动作**，与写成管道、命令替换还是循环无关。

不是守卫退化：那三种写法一直拦得住，用户这次用的命令替换形态**从来没被覆盖**。

## 判据（现在的）

同一命令里同时满足：
1. 按模式挑进程：`pgrep -f` / `pkill -f` / `ps … | grep`
2. 出现 `kill` / `killall` / `xargs … kill`
3. 没有白名单：`comm=` / `pidof` / `--pid` / `ppid`

⇒ 拒，并给出两条合法路径：拆成两条命令（先看清单、核对 PID 再 kill），
或带 `comm` 白名单批量过滤。

同一条命令里出现两个动作（一个挑进程、一个杀进程）就会把调用者自己算进匹配集 ——
这正是要拒的结构，不必管它写成什么形状。
