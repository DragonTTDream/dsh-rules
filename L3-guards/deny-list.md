# 守卫该拦什么

守卫是**脱离模型**的一层：模型看不到它，也绕不过它。它只做一件事——
在工具真正执行前做一次单调检查，命中就拒，并把拒绝原因回灌给模型。

## 一、该下沉到守卫的判据

同时满足三条才下沉，缺一条就留在提示层：

1. **反复违反**：提示层已经写过，仍然会犯。
2. **可静态判定**：只用命令字符串 / 参数就能判，不需要理解意图。
3. **误拒代价低**：拒错的后果明显小于放过错的后果。

## 二、拦截清单

| 编号 | 拦什么 | 判据 | 对应规则 |
|---|---|---|---|
| G-1 | 按完整命令行匹配的进程查询/杀灭 | 命令含 `pkill -f` / `pgrep -f` | R-07 |
| G-2 | 破坏性动词 | `rm -rf`、`git reset --hard`、`git clean -fdx`、包管理器卸载、`DROP`/`DELETE`、格式化 | R-03 R-12 |
| G-3 | 绕过手法 | 把破坏性动词拆成变量、`eval`、`$(...)` 拼接、`base64` 后执行 | R-03 |
| G-4 | 重启 + 后台叠加 | 同一条命令里既有服务重启又有后台拉起 | R-07 R-12 |
| G-5 | 脚本内的重启 | 提交的脚本体里含服务重启 | R-12 |
| G-6 | 无快照写宿主消费集 | 写入路径命中"运行中服务在读"的清单，且该路径无新鲜快照 | R-12 |

## 三、设计要求（这几条比清单本身重要）

1. **拒绝消息是路标，不是墙。** 回灌给模型的一句话要说清"为什么拒 + 该怎么做"，
   否则模型只会换个写法再撞一次。
2. **fail-open，绝不 fail-closed。** 守卫自身出错时一律放行并记日志；
   防线故障不能变成业务锁死。
3. **单调**：守卫在所有其他前置检查之后求值，不依赖它们的结果，也不被它们短路。
4. **可审计**：每次拒绝追加一行日志（时间、工具、命中原因、命令前缀）。
   没有日志的守卫等于没有守卫。
5. **有逃生口**：一个开关能降级成"只记日志不拒绝"，供观察期与新规则灰度使用。
6. **豁免白名单要显式**，不用正则宽匹配——宽匹配的豁免就是没有豁免。


改判别器的唯一规矩：**先跑矩阵**。矩阵红了要先弄清是"规则变严了（该更新用例）"
还是"判别器坏了（该修代码）"——两者看起来一样，处理方式相反。
