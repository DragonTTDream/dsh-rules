# 防复发规格（把一次错误变成一层拦截）

> **用途**：每犯一次错，按这份流程决定"补到哪一层、怎么补、怎么证明它真的拦得住"。
> **目标**：**越用越顺手，而不是记忆文件越写越长。**
> **验收**：每条加固都必须带一个"不装就红"的负样本；否则只是写了一段散文。

## 一、四层强制力 + 一个检索层

| 层 | 谁在读 | 每轮成本 | 模型能违反吗 | 放什么 | 闸门 |
|---|---|---|---|---|---|
| **L0** 常驻规则 | 每轮注入 | **最贵**（14336 字节硬上限） | 能 | 每轮都必须守、且无法静态判定的 | 合成超限即不许装 |
| **L1** 场景规则 | 进该目录才注入 | 0 | 能 | 那个任务域特有的约定 | 无 |
| **L2** 技能 | 命中触发才加载 | 0（延迟加载） | 能 | 只在动手那一刻才需要的做法 | 单条 <2000 token |
| **L3** 守卫 | 代码里，模型看不见 | 0 | **不能** | 反复犯、且能用一条规则判出来的 | 必须有单测 |
| **经验库** | 失败时 grep | 0 | —（检索层，不是强制层） | 症状 → 判据 → 正解 | active ≤20 条 |

**口诀**：能靠自觉 → L0；只在某场景 → L1；只在动手时 → L2；已犯过且能机器判 → **L3**；只值得查 → 经验库。

## 二、判层四问（按顺序问，先问机检）

1. **能用一条命令/一个正则判出来吗？** 能 ⇒ **L3**，到此为止。
2. **只在"动手做某件事"时才用得上吗？** 是 ⇒ **L2**。
3. **只对某类目录/任务成立吗？** 是 ⇒ **L1**。
4. **每轮都得在吗？** 是 ⇒ **L0**（先看余量，装不下先瘦身）。
5. 都不是（只需"下次查得到"）⇒ **经验库**。

> L3 优先，因为它**不依赖模型自觉**。同一形状重复犯（I 型错误）默认往 L3 推。

## 三、七步加固流程

| 步 | 动作 | 判据 |
|---|---|---|
| 1 | **抓现象** | 一句原话 + 一条可复现命令 + 实际 vs 期望 |
| 2 | **取证到字节/日志** | 能指出"谁、在哪一行、做了什么"；指不出 ⇒ 只是候选机理，不许写根因 |
| 3 | **归类** | 知识缺口（不知道）/ 纪律缺口（知道没做）/ 机制缺口（做了没拦住） |
| 4 | **判层**（第二节） | 能说出为什么不是更高一层 |
| 5 | **写** | 按 [写法规格.md](写法规格.md)：11 条硬要求 + 五段 |
| 6 | **验（必须）** | 造负样本：不装这条它必须红，装了必须绿 |
| 7 | **装 + 记** | 快照/回退命令 + `last_verified` + CHANGELOG 一行 |

**第 6 步最容易跳过，也最容易返工**：没有负样本的加固，等于"我记得它修好了"。

## 四、验收：负样本是硬要求

- **L3**：单测里必须有"不启用该规则 ⇒ 用例失败"的对照组
- **L2/L1/L0**：至少给一条"错误写法"的对拍（写错时的现象 vs 写对时的现象）
- **经验库**：判据列能当场跑，结果与"症状"一致

一句话判据：**这条加固删掉之后，我能指出哪条检查会红吗？** 指不出 ⇒ 它拦不住任何东西。

## 五、可回退（每次加固都能撤销）

- **文件类**：先快照（只留最新一份），再写下回退命令
- **配置类**：一行备案（失败症状 + 回退命令 + 验证命令）
- **守卫类**：每次改都有单测与备份；灰度期用开关（`enabled:false`）而不是删代码
- **闸门在生效之前跑**：静态判据（语法/配置解析/单测）红了当场回退，别让服务起来再修

## 六、防膨胀三招（规则库会长胖，必须定期瘦）

| 招 | 做法 | 判据 |
|---|---|---|
| **合并** | 同层三条讲同一件事 ⇒ 合成一条 | 删掉两条，剩下那条仍能执行 |
| **下沉** | 散文里能机检的部分 ⇒ 抽成 lint/test，正文只留指针 | 抽出后正文缩短且行为不变 |
| **删除** | `last_verified` 超过两个月的 active ⇒ 降 draft 或归档 | 归档后没有任何检查变红 |

预算（硬数字）：**L0 ≤14336 字节**、**L2 单条 <2000 token**、**经验库 active ≤20 条**。
超了按上面三招处理，不许"先加上去以后再说"。

## 七、反例（真实踩过）

- 把事故记录整段塞进 L0 ⇒ 每轮都为历史付费
- 同一现象反复改判据（三次）⇒ 该停手去指名取证，不是改第四次
- 可机检的规则留成散文 ⇒ 模型照样犯，只是没人拦
- 加固不写负样本 ⇒ "修好了"只是记忆，不是证据
- 守卫用**命令文本粗匹配** ⇒ 误伤无关命令，甚至拦住"修这个守卫"的操作（实测死锁）
- 只改消费端容错、不改产出方契约 ⇒ 同一类错换个输入又来

## 八、社区依据

| 依据 | 对应本规格 |
|---|---|
| **纵深防御（defense in depth）** | 四层不是冗余，是不同失效面：自觉会疲劳、守卫不会 |
| **Google SRE：自动化优先于文档**（prose rots） | 第 9 条：能机检就下沉，散文会烂 |
| **shift-left**（拦截前移） | 判层顺序先问"能否机检"，即尽量左移到 L3 |
| **RFC 2119**（MUST/SHOULD/MAY） | 强度分级，冲突时按强度裁决 |
| **Parse, Don't Validate** | 判定看结构化事实（工具名/退出码/字段），别靠"命令里出现过什么" |
