# 脚本被错误解码：中文注释吃掉下一行的变量

**状态**：active（2026-10-22）

## 症状

- 自己写的脚本（含中文注释）跑起来"莫名失败"：变量为空、语法报错、参数缺失
- 报错指向的**行号是对的，但那一行看起来完全没问题**
- `rc = -2147467259`（`0x80040005` 语法无效）；或 `$var` 为空导致下游拿到空参数
- 同脚本在别的机器/别的编辑器里正常

## 判据

- **写入编码 ≠ 解释器读取编码**：PowerShell 5.1 读无 BOM 文件时**不猜编码**，回落到系统 ANSI 代码页
  （中文 Windows = GBK/CP936）。UTF-8 的中文按 GBK 解码 ⇒ 多字节序列与后续字节**粘连**，
  尾字节可能吃掉换行/`$`/引号 ⇒ 下一行变量被并进注释或字符串
- 判据三连：
  1. `file <脚本>` 看编码，`head -c 16 <脚本> | od -An -tx1` 看有没有 BOM（`EF BB BF`）
  2. 现象是"**语法错误但那一行看着没问题**"或"**变量凭空为空**"
  3. 去掉中文注释/改成 ASCII-only 后立刻正常 ⇒ 就是它

## 正解骨架（按稳健度）

1. **脚本正文只用 ASCII**：中文注释改英文或放到文档里（最稳，跨解释器/跨机器都不炸）
2. 需要中文就必须带 **UTF-8 BOM**（PS 5.1 见 BOM 才按 UTF-8 解）
3. 或统一用 **PowerShell 7+**（默认 `utf8NoBOM` 读取，规则与其他平台一致）
4. 生成脚本的环节要**显式指定编码**（Python `encoding="utf-8-sig"`、`Out-File -Encoding utf8BOM`）

## 反例

- 在 PS 5.1 里给脚本加 `# -*- coding: utf-8 -*-`（那是 Python 的约定，PowerShell 不认）
- 只把文件"另存为 UTF-8"但没 BOM —— 等于没变
- 靠"重打一遍注释"碰运气 —— 字节排布变了就"好了"，换个字又炸
- 修消费端兜底（改脚本去容错）而不修产出端的编码声明
