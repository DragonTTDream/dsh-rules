# 秒退无输出：程序根本没启动

## 症状

- 进程**毫秒级消失**
- **零输出**：stdout / stderr 都是空
- 日志文件一个字节都没有
- 计划任务里看不出异常，只是"没效果"

## 判据

- exit code = **`0x2`（找不到文件）/ `0x3`（路径不存在）/ `9009`（命令不存在）**
- 计划任务：`LastTaskResult` = `0x80070002`
- **程序侧没有任何输出** —— 因为它从未被执行

一句话判据：**"毫秒级消失 + 零输出"永远是启动失败，不是程序崩溃。**

## 正解骨架

1. 先拿 exit code，别翻程序日志：
   ```cmd
   schtasks /query /tn "<任务名>" /v /fo LIST | findstr /i "结果 Result"
   ```
   ```powershell
   (Get-ScheduledTaskInfo -TaskName "<任务名>").LastTaskResult
   ```
2. `0x2` ⇒ 目标路径没被找到：先查引号、盘符、工作目录
3. 路径含空格 ⇒ 转 [Windows引号被切.md](Windows引号被切.md)

## 反例

- 看到零输出就去程序里加日志 —— 加一百行也没用，它没跑
- 反复调程序参数 —— 参数根本没被解析，改动无效
- 用 `tasklist` 判断"起没起来" —— 比 `LastTaskResult` 晚且更脆

## 边界

适用「进程**没起来**」这一类；**不适用**「起来了又秒退」——那要看程序自己的 exit code 与日志。
`127` = 命令不存在（Linux/shell），`0x2` = 文件不存在（Windows），`9009` = 命令不存在（cmd）——按平台对号。
不覆盖「起来了但没效果」：那属于「跑了没作用」，判据是目标文件的 mtime/哈希。
