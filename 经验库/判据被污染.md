# 判据字符串写进被检文件 ⇒ 语法报错也能让它"通过"

## 症状

- 脚本其实没跑起来（语法错误 / 编码错），但我的完成判据"命中"了
- 报错回显里出现大段源码——判据 token 就在源码里
- 同一判据时对时错：换个文件名 / 换个报错级别就变
- "通过"的那一刻没有任何别的证据：没有产物、没有日志、时间戳也没推进
- 收官声明写着「PASS」，再问一句"产物的 mtime 是多少"答不上来

## 判据

- 判据的每一次命中，都要能指出它是**执行写出来的**还是**报错回显带出来的**。说不出 ⇒ 判据无效。
- 动手前一条命令：`grep -c '<TOKEN>' <被检文件>` 必须为 **0**；非 0 ⇒ 这个 token 作废，换一个不写进被检对象的。
- 跑完收口用**外部量四条**，全过才算通过：
  1. 退出码 `0`
  2. 产物存在（`test -f`）
  3. 产物 mtime **晚于**脚本 mtime
  4. 产物内容命中（`grep -c` ≥ 1）
- 判据与被检对象不得共用同一条通道（同一个 stdout / 同一个文件 / 同一段源码）。

## 正解骨架

判据只在运行时由外部注入，不落进被检文件的任何字节：

```bash
TOKEN="done-$(date +%s)-$$"                 # 每次不同，历史回显撞不上
grep -c "$TOKEN" "$SCRIPT" && { echo "TOKEN 污染：判据在被检文件里"; exit 1; }
sleep 1                                     # 让 mtime 可比
bash "$SCRIPT" "$TOKEN" "$OUT"; rc=$?
if [ "$rc" -eq 0 ] && test -f "$OUT" \
   && [ "$(stat -c %Y "$OUT")" -gt "$(stat -c %Y "$SCRIPT")" ] \
   && grep -q "$TOKEN" "$OUT"; then echo PASS; else echo "FAIL rc=$rc"; fi
```

- 更省事：根本不用 token，用产物固有量（行数 / 哈希 / 最新一行的时间戳）
- 判"通过"时必须同时能报出**至少一个与判据无关的量**（mtime、字节数、进程 PID + 启动时间）

## 反例

- 用"回显里出现 DONE / 完成 / SUCCESS"判完成
- 把判据写进脚本注释、变量名、`echo` 文案里（报错会把整行源码打出来）
- 只看 `grep` 有没有命中，不看命中位置：`grep -n` 能看出命中的是源码区还是产物区
- 同一个 token 跨会话复用（撞上一次的回显或历史日志）
- 判据放在被检对象里自证（脚本自己 `echo PASS`）
- `bash -n` 通过就认为脚本能跑（只证明语法完整，不证明执行）

## 边界

只约束「用文本匹配 / 回显当完成判据」的场合。编译器、测试框架自身返回结构化结果（退出码 + 报告文件）时按它们的约定即可。
不解释「判据可靠但实现做错了」：谁在汇报见 [成功声明不算证据.md](成功声明不算证据.md)，判据是否独立见本条。
