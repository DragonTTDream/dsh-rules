# 链式命令成功 ≠ 中间产物到位（`&&` 把失败吃成静默）

## 症状

- `scp ... && sc create ...` 整体退出码是 0，但远端报「系统找不到指定的文件」
- 下游那一步回显「创建成功 / REGISTERED OK」，而上游那件实物根本没送到
- 中间某步失败后，后面的步骤**一声不响地全跳过**，终端里没有错误行
- 重跑一次仍然"成功"，因为每次都在同一处短路
- 排查时发现：源路径是凭记忆写的（以为在 A 目录，实际在 B 目录）

## 判据

- `&&` 只传递**退出码**，不传递「实物是否存在」。A 成功 ≠ A 想做的搬运成功。
- 当场三连，缺一即不算送达：
  1. 本机源：`test -f <源>` 为真
  2. 对端目标：`ssh <主机> 'test -f <对端真实路径>'` 为真
  3. 下游消费点：注册/启动后它**实际引用的路径**非空且等于目标（`sc qc <服务名>` 的 `BINARY_PATH_NAME`；`tasklist` 里进程的映像路径）
- 反查证据：能说出「哪一步、哪个路径、哪个退出码」；说不出 = 你只是看到最后一步成功了。

## 正解骨架

每步自己带判据，不串联：

```bash
[ -f "$SRC" ] || { echo "SRC MISSING: $SRC"; exit 1; }
scp "$SRC" "$HOST:$DST" || { echo "SCP FAILED rc=$?"; exit 1; }
ssh "$HOST" "test -f '$DST'" || { echo "DST MISSING: $DST"; exit 1; }
ssh "$HOST" "<注册或启动命令>" || { echo "REGISTER FAILED"; exit 1; }
ssh "$HOST" "<读回下游实际引用的路径>"        # 第三连：消费点核对
```

- 分段写、每段一个显式错误出口：短路的目的从"省事"换成"每步都报告自己失败了"
- 跨机器搬运的路径在**两个命名空间里各核一次**（本机源 / 对端目标），不靠 `&&` 传递信任
- 目录存在不算文件到了：一律 `test -f <确切文件>`

## 反例

- 用 `A && B && C` 串联跨机步骤，靠"没报错"当成功
- 把下游命令的成功回显（"创建成功"）当成上游搬运成功
- 只看整条链路最终 exit code：短路后它反映的是**第一个失败步**，不是最后一步
- 用 `ls <目录>` 代替 `test -f <文件>`：目录在 ≠ 文件到
- 源路径凭记忆写，写完不核一眼
- 指望 `set -e` 纠正链式行为：它在 `&&` 链里的生效粒度与直觉不同

## 边界

只约束「跨机器 / 跨命名空间」且上游产出是下游必需实物的链（scp / ssh / schtasks / sc create / 远端脚本）。
同一台机器上 `cmd1 && cmd2` 且 `cmd2` 的输入直接来自 `cmd1` 的产出时，短路语义通常够用。
不解释「传过去了但内容坏了」——那要哈希对拍；判据本身是否可靠见 [判据被污染.md](判据被污染.md)。
