## 按场合看（动手前）

> 症状索引只在**出事之后**有用；这一栏是**动手那一刻**该看的。
> 命中场合 ⇒ 先读对应文件再敲命令。跨机场合的强制版在 `L1-scoped/remote-exec.md`（已进工作区 `AGENTS.md`）。

| 我要做的场合 | 先读 | 为什么 |
|---|---|---|
| 命令要送到另一台主机（ssh / scp / schtasks / sc create / 远端 ps1） | [../L1-scoped/remote-exec.md](../L1-scoped/remote-exec.md) | 出错在本机看不见：失败被短路吃掉、编码被对端改写、判据被回显伪造 |
| 写 Windows 侧脚本（`.ps1` / `.bat`） | [脚本被错误解码.md](脚本被错误解码.md) | PS 5.1 读无 BOM 文件按 GBK 解，中文与相邻字节粘连 |
| 要声明"这个任务完成" | [判据被污染.md](判据被污染.md) | 判据落在被检文件里时，语法报错回显就能让它"通过" |
| 把多个步骤用 `&&` 串起来 | [链式短路.md](链式短路.md) | 短路会把中间步的失败变成静默跳过 |
| 收到短到解析不出动作的消息（`？` / 单字 / 只有标点） | [输入不可解析时不猜意图.md](输入不可解析时不猜意图.md) | 单字符的先验是误触；猜出来的意图会被当成授权写进后续动作 |

## 按归属层看（该在哪修）

| 归属 | 条目数 | 该做什么 |
|---|---|---|
| `harness` | 3 | 下沉 L3 守卫 / lint / 配置——模型犯不了 |
| `interaction` | 3 | 改接口设计（别让成功由被检查者自报；别让判据与被检对象共用通道；别把解析不出动作的输入当指令） |
| `model` | 6 | 只能进 L0/L2 的判据与知识——模型得自己守住 |

## 维护命令

```bash
bash bin/lint-gotchas.sh            # 只检查（五段/时间戳/归属/SLA/去标识/长度）
bash bin/lint-gotchas.sh --refresh  # 真跑每条 verify_cmd，通过则把 verified_at 盖成今天
```
