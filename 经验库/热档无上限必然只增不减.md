# 热档无上限必然只增不减（有 cap 的被管住，没 cap 的涨到 216 KB）

## 症状

- "这文件怎么这么大了" / "方案文件比正文大几十倍" / "打开就滚几十屏"
- 文件里同时躺着：方案本体、逐日施工日志、排障试错、会话逐字流水、备份与回退台账
- 标题编号乱序（`## 11` → `## 15` → `## 10`）、出现「续 / 续2 / 续3 / 续4」
- 大量单行超长（会话逐字记录被整条贴成 bullet），同一结论在 5–8 处重述
- 同项目里**有上限的常驻文件一直被人瘦身，没上限的文件从来没人管**

## 判据

- 打开文件头 8 行，**有没有 `cap:` 行**？没有 ⇒ 这个文件必然只增不减，立即补声明并下沉。
- 跑闸门：`bash bin/cap-check.sh --require-cap <工作区目录>` —— 报「无上限声明」= 无闸门；报「超上限」= 当场下沉。
- 拆角色的判据（四问）：这段是**方案本体**（要改的）/**施工日志**（做过的）/**排障记录**（试过的）/**会话流水**（说过的）？后三类一律下沉，热档只留一行指针。
- 结案条目里出现「续」= 已经违规：定稿条目只改状态行，新结论 = 新条目。

## 正解

**照 logrotate 的三件套写闸门：声明大小 → 到线轮转 → 保留份数**（社区同源：logrotate `size`+`rotate N`+`compress`；Wikipedia 单节 >50 KB 拆 + `{{main}}` 指针；SKILL.md under 500 lines；PEP/RFC 定稿后不再实质修改）。骨架：

1. **每个共用文档头部写 cap 行**（frontmatter 内，8 行内可见）：
   `cap: 30KB`（方案/README/落地页）· `cap: 50KB`（日志/流水/取证）· `cap: 500lines`（技能正文）
2. **闸门脚本可数化**：解析 cap 行 → 比对字节与正文行数 → 超限报红并提示去向；无 cap 行直接报红。
   数字进脚本（本机事实），**不进常驻规则正文**（同 R-07 的阈值处理方式）。
3. **到线就搬，不删不压缩**：最老段落整段搬进 `日志/<日期>.md`，原处替换为一行
   `> 详见：日志/<日期>.md#条目N（本处不复制）`。
4. **搬完做守恒对拍**（判据不得由搬的调用自报）：
   - 逐段 `sed -n '起,止p' 快照 | md5sum` == 新文件正文 md5
   - **覆盖测试**：快照每一非空行必须能在「主文件 ∪ 全部新档」里找到，缺失行数应为 0（只允许授权删除的行）
   - 行数守恒等式：原行数 = 保留 + 搬走 + 新增（frontmatter/指针/状态节）
5. **落地页只做交通警**：一个目录一份 README，一行一条指针，正文不进落地页。
6. 共用文档写 `owner:` 与 `reviewed:`；复查 = **真跑一遍验证命令**，不是在文里改字。

## 反例

- **只写"注意精简"**：没有数字就没有闸门，收尾时没人数，下轮继续追加 ⇒ 与没修一样。
- **上限写进常驻规则正文**：规则每轮注入，数字一变动就是全量上下文税；数字放部署脚本，规则只留指针。
- **下沉时顺手"精简"正文**：搬 = 逐字搬。改写了正文，守恒对拍必炸（md5 不等），而且再也证明不了没丢东西。
- **同一段内容在热档留一份、冷档再留一份**：那是复制不是指针，体积只增，两处以后互相矛盾。
- **给日志档设很小的 cap 然后删旧内容**：日志是冷档目的地，设上限只允许**分档**（拆文件），不许删。
- **压缩成 gzip 当"下沉"**：压缩后 grep/对拍判据全失效，等于把证据销毁。
- **把"续2/续3/续4"继续往结案条目后面写**：定稿与草案混浆，读者无法判断哪句还有效（PEP/RFC 明令禁止的形态）。

## 边界

- 适用：会被反复追加的共用文档（方案档、README、MEMORY、施工日志、交接档）。
- 不适用：一次性交付物（写完就冻结的报告）、数据目录（ROM/镜像/权重）、快照与归档目录（冷档，是下沉目的地）。
- 不适用：机器生成的产物（由生成者管体积）。
- 与「热档只留指针」的关系：本条补的是**"什么时候必须动"**——没有 cap 数字时，那条纪律等于没有。
