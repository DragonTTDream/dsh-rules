# 成功声明不算证据：存活探测由谁汇报

## 症状

- 启动脚本 `exit 0`，日志里写着 `task started ok`
- 但**没有进程在跑**，或者进程 0.1 秒就死了
- 探测"起没起来"的结果与真实状态相反
- 换台机器/换个会话查，结论又不一样（跨会话属性访问被静默丢弃）

## 判据

- **成功判据由被检查的那个调用自己汇报 ⇒ 不算证据**
- 具体形态一：`cmd >/dev/null 2>&1 &` 后紧跟 `echo ok` —— 命令不存在、进程瞬死，都被 redirect 吞掉，`$?` 由末尾 `echo` 决定
- 具体形态二：`set -e` 对**后台作业**失败无效（实测：拼错命令仍 exit 0）
- 具体形态三：`$!` 拿到的 PID 可能是个**瞬死进程**的编号；`kill -0` 通过不代表它在干活
- 具体形态四（Windows）：靠 `Path`/`CommandLine` 属性跨 session 取进程信息，**跨 token 访问会被静默丢弃**，返回空而不是报错

## 正解骨架

**带外三件套**（完全不看启动脚本的输出）：

```bash
pid=$!
sleep 1                                   # 等过「瞬死窗口」
ps -o pid,ppid,sid,etime,comm -p "$pid"   # 身份三元组：comm 对、SID 独立、ELAPSED 在增长
stat -c '%y' heartbeat.log                # 心跳 mtime 在推进 = 它还在动
```

- **PID 单独不可信**：脚本退出后 PID 会被复用/失效，必须 **PID + comm + start-time** 一起看
- **Windows**：`tasklist /FI "IMAGENAME eq X.exe" /FO CSV /NH`（含 SESSION 列），或
  `schtasks /query /tn <名> /v /fo LIST` 看 `LastTaskResult`
- **窗口类 GUI 程序**：要看 SESSION 是否为你登录的会话（Session 0 = 服务会话，界面不可见）

## 反例

- 只看 `exit 0` 或日志里的 "ok"
- 用 `pgrep -f <模式>` 判断 —— 模式也会匹配到你自己这条命令
- `kill -0 $pid` 通过就认定活着 —— 它只证明"此刻存在"，不证明"是那个进程、还在干活"
- 相信工具返回的 success 字段（"返回 TRUE ≠ 做对了"）

## 边界

只约束**后台/异步/跨会话**的存活判定；前台单条命令的 `exit 0` 仍然可信。
GUI 程序还要额外看 **SESSION 列**（Session 0 的界面不可见），本节只给出判据入口。
不覆盖「进程活着但卡死」：那要看心跳文件 mtime 是否推进。
