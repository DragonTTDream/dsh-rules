# 不可解析的输入不是意图，更不是批准

> 一句话：**解析不出动作的输入 = 缺口。缺口既不是指令，也不是同意，也不是"继续"。**

## 症状

- 用户发来一个 `？`，我回「明白——不再问了」，然后按**自己推断的意图**继续干活
- 用户随后问："结果你紧接着就解读成『明白——不再问了』，这是怎么回事"
- 事后能复盘出"我当时觉得他是嫌我啰嗦"——**没有任何一条消息这么说**
- 顺着推断改下去，改的是用户的规则文件（L0），而授权来自更早那一条消息，不是这一条
- 把符号消息当"默认同意"：`？` / `。` / 空白 / 单个表情 ⇒ 当成"他没反对"，于是推进、写盘、宣布完成
- 报告里出现「按你的意思」「那就这么定了」，而本轮只收到过一个标点

## 判据

- 一条消息能不能解析出**动作**？解析不出 ⇒ 它是缺口，不是指令。
- 可判定形态（可跑，见 `bin/gotchas-verify/unparsable-input.sh`）：去掉标点、空白、表情之后，
  剩余里**没有任何 CJK / 字母 / 数字** ⇒ **不可解析**。
- **批准是另一道闸，不可解析输入永远过不了它**：授权 = 本轮消息原文里出现明确授权词
  （批准 / 同意 / 授权 / 做 / 删 / 改 / 装 / 重启 / 按建议 / 全做）+ 能被指到具体动作。
  不可解析输入既没有授权词也没有动作 ⇒ 三条都判"否"：不是指令、不是批准、不是"继续"。
- 出现"我觉得他是想…""大概是嫌…"这类句子 ⇒ 当场停下，那是推断不是事实（R-01/R-04）。
- 判据句：**这句话如果是错的，我下一步会做错什么？** 答不出 ⇒ 不许动。

## 正解骨架

不可解析的输入一律当缺口，四行说完再等：

```
我看到的输入：`？`（无法从中解析出动作）
我能想到的可能：① 嫌我啰嗦 ② 没看懂上一段 ③ 误发 ④ 想问别的
不猜：以上都不作为行动依据，也不作为授权依据
要你一句：是哪一个？（或者直接说要我做什么）
```

硬规矩（顺序执行，任一命中即停）：

1. **禁当批准**：不可解析输入 ⇒ 授权判定直接返回"无授权"。**否定句优先**（"先别""不要"不算授权），
   **上一轮及更早的授权不结转**（R-03）。
2. **禁改盘**：本轮无授权 ⇒ 不写 / 不移 / 不删 / 不重启 / 不安装；只回问。
3. **禁当"继续"**：不可解析输入不得被写成「继续」「明白」「收到，你是说…」；
   引用用户原话必须用 `session_facts` 逐字取（R-13）。
4. **例外只有一个**：上一条消息里**已经有明确动作且已被批准**（"AB 先执行""5 步全做"），
   那条批准继续管它已覆盖的范围；本条符号消息**不扩大也不新增**任何授权。

## 反例

- 把 `？` 解读成"嫌我啰嗦"，于是压缩答复并跳过提问，直接改盘
- 把 `？` 解读成"没看懂"，于是重发一遍更长的表格（用户更烦）
- 把 `？` 当成"没反对" ⇒ 批准隐含成立 ⇒ 执行破坏性动作（本条最贵的形态）
- 在报告里写"按你的意思…"——用户从没说过那个意思
- 用"用户没说不，就是默认同意"给删除/重启找理由
- 误发是真实存在的：单字符消息的**先验**是误触，不是指令

## 边界

- 不适用于**能解析但表达简短**的输入（"AB 先执行"只有 6 个字符，但动作明确 ⇒ 是指令）。
- 判据不是长度，是「能否不靠猜测抽出一个动作」。
- 单字肯定词（"好""行""嗯"）：可解析为**认可**，**不等于授权**——授权仍按第 1 条判：
  要能指到具体动作 + 本轮明确授权词。"好" 不覆盖重启/删除这类一次向操作。
- 授权判定归守卫（按 harness 记录判），本条只管模型侧不猜、不自封批准。
