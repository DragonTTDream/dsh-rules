# dsh-rules — 给 agent 装的一套可分层、可回退的行为约束

一套**按强制力分层**的行为约束库：从"模型每轮都看到、靠自觉"的常驻规则，
一路下沉到"脱离模型、由代码强制"的守卫。目标是让模型在你自己的机器上
**越用越顺手**——每犯一次错，就往正确的层里补一条，而不是让记忆文件越写越长。

> 本仓内所有事故案例均已**去标识化**改写：不含主机地址、内网路径、账号、
> 模型名、项目名。个人定制与本机装配放在 `local/`（`.gitignore` 已拦），
> 或用 DSH 原生的 `AGENTS.local.md` 覆盖层，二者都不进公开仓。

## 一、分层：一条约束该放哪一层

| 层 | 名字 | 谁在读 | 占每轮上下文 | 模型能违反吗 | 放什么 |
|---|---|---|---|---|---|
| **L0** | 常驻规则 `always-on` | 每轮注入 | 是（最贵） | 能 | 每轮都得守、且无法静态判定的 |
| **L1** | 场景规则 `scoped` | 进入该目录才注入 | 否 | 能 | 那个任务域特有的约定 |
| **L1.5** | 个人覆盖 `local` | 同 L1 | 否 | 能 | 你的口味、你机器上的偏好 |
| **L2** | 技能 `skills` | 命中触发条件才加载 | 否 | 能 | 只在动手那一刻才需要的做法 |
| **L3** | 守卫 `guards` | 代码里，模型看不见 | 否 | **不能** | 反复犯、且能写成 if 判断的 |

### 优化口诀

> 能靠自觉 → 写 **L0**；只在某场景要 → 下沉 **L1**；只在动手时才需要 → **L2**；
> 模型反复犯、且能写成 if 判断 → **必须下沉 L3**。

判断一个错误该补哪层，只问四句：

1. 这条约束每轮都得在吗？是 → L0。
2. 它只对某类目录/任务成立吗？是 → L1（或 L1.5，如果是个人口味）。
3. 它只在"动手做某件事"时才用得上吗？是 → L2。
4. 它已经犯过不止一次、而且能用一条命令字符串判出来吗？是 → **L3**。

## 二、为什么这样分层

同一条约束在四个层的任何一个都能落地，但代价完全不同：

- 放 L0 = 每轮都付 token、且**模型可能不看**；
- 放 L3 = 零上下文成本、**模型绕不过**，但只对能静态判定的东西有效，且不灵活。

所以分层的真正作用是：**把"要靠模型自觉"的部分压到最小**。
一条约束下沉一层，系统的可靠度就高一档、上下文的负担就低一档。

## 三、每条规则的元数据

规则内容不是最重要的，**它因为哪次错而存在**才是：

```yaml
id: R-03
title: 改动前拿授权
layer: L0
visibility: public        # public | local
since: 2026-10-03
why: 模型擅自扩大授权范围，把用户没点名的条目一并撤下
evidence: incidents/INC-2026-10-03-overreach.md
judge: 本次改动能否指到一条真实用户消息？指不到就不动
enforced_by: [prompt]     # prompt | skill | guard
```

- `judge` 是**可判定判据**——能不能写成 if，决定它最终该不该下沉到 L3。
- `evidence` 指到事故，删规则前先看那次错还在不在。
- `enforced_by` 有多种时，说明这条规则目前被多层覆盖（正常，但要知道谁在兜底）。

## 四、五步优化循环

| 步 | 动作 | 产物 |
|---|---|---|
| ① 记账 | 模型犯错当场记：症状、原命令、模型原话、复现方式 | `incidents/INC-<日期>-<短名>.md` |
| ② 定性 | 按上面四问定位到层 | 结论一行：为什么是这层 |
| ③ 下沉 | **只改一处**，commit message 指到事故 id | 一个规则文件 |
| ④ 回归 | 造陷阱用例：同一错再来时能自动抓出来 | `bin/lint.sh` 用例 / 守卫矩阵 |
| ⑤ 回填 | 规则的 `since` / `why` / `evidence` 三字段 | 元数据完整 |

## 五、目录

```
L0-always-on/     常驻规则，一条一个文件；assemble.sh 拼成单一 AGENTS.md
L1-scoped/        场景规则模板与示例（目录级附加、按语言分目录的放法）
L1.5-local/       个人覆盖层模板（去标识化后公开，供借鉴）
L2-skills/        10 个技能原文（含 references/），直接可装
L3-guards/        守卫：该拦什么（deny-list）+ 判别器实现 + 陷阱用例
L4-plugins/       自制的「能力型」插件：self-recall、vision-forward；rules-by-glob 是「按扩展名附加规则」的可行性结论
incidents/        事故台账 —— 整个仓库的燃料
research/         带来源的调研
bin/lint.sh       分层校验 + 去标识化黑名单，CI 可直接跑
bin/assemble.sh   L0-*/ 拼成 AGENTS.md（拆分给人维护，合并给机器做）
```

## 六、怎么装到自己机器上（DSH）

本仓的 L0/L1/L1.5 与 DSH 原生的注入点一一对应：

| 层 | 装到哪 |
|---|---|
| L0 | `$DSH_HOME/AGENTS.md`（用户全局，每轮注入） |
| L1 | `<工作区>/AGENTS.md`（从项目根到 cwd 逐级生效，越具体越优先） |
| L1.5 | `<工作区>/AGENTS.local.md`（DSH 原生覆盖层，加进 `.gitignore`） |
| L2 | `$DSH_HOME/skills/` + 各模式技能的根目录白名单 |
| L3 | 插件形式挂到 `ctx.tools.guard()` |

```bash
# 只拼 L0，不装
bin/assemble.sh > /tmp/AGENTS.md

# 装 L0（先备份你自己的）
cp "$DSH_HOME/AGENTS.md" "$DSH_HOME/AGENTS.md.bak-$(date +%Y%m%d-%H%M%S)"
bin/assemble.sh > "$DSH_HOME/AGENTS.md"

# 校验：分层正确 + 无本机事实泄漏
bin/lint.sh
```
