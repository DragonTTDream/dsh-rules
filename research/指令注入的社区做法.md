# 指令文件的发现与注入：社区怎么定"在哪找、找几个、谁覆盖谁"

**结论一句话**：没一家用**目录规则**承载"任务型规则"（"命令要离开本机"这种场合）。
任务型规则在社区里的载体是 **skills（按需加载）** 与 **hooks / permissions（确定性拦截）**；
目录型 `AGENTS.md` 只承载"这个目录里的约定"，且**不许指望它必被执行**。

## 一、对比

| | 发现边界 | 合并语义 | 子目录文件 | 全局层 | 硬规则放哪 |
|---|---|---|---|---|---|
| **Claude Code** | 从 cwd 向上**逐级到文件系统根**，另有企业策略目录与 `~/.claude/` | 全部拼接，越具体越优先（跨层冲突＝未定义行为） | **启动不加载**，读到该目录文件时才加载 | `~/.claude/CLAUDE.md` | `settings.json` permissions / hooks / linter / pre-commit |
| **AGENTS.md 标准（Codex）** | 从**被编辑的文件**向上找**最近**一个 | **最近者胜**，root 作默认 | 天然按文件生效 | 代理自己的全局目录 | approval policy |
| **Gemini CLI** | cwd → 父目录**直到 `.git` 根**，另加**cwd 下子目录扫描**（尊重 `.gitignore`） | 全部拼接 | 主动扫描 | `~/.gemini/GEMINI.md` | ——（文档未给） |
| **Cursor** | `.cursor/rules/*.mdc`，**不看目录继承** | frontmatter 的 `globs` / `alwaysApply` 决定**何时**激活 | 同左（也读根与子目录 `AGENTS.md`） | 用户规则层 | hooks |
| **DSH 现状** | 向上找最近 `.git`；**没有 `.git` 就停在 cwd** | root→cwd 全拼接 + 触碰子目录时补 | 按 touch 增量加载 | `~/.dsh/AGENTS.md` | `ctx.tools.guard`（deny） |

## 二、原文（带来源）

- Claude Code：「walks up the directory tree from your working directory, checking each level for a `CLAUDE.md`」；
  子目录「are not loaded at launch. They load on demand when Claude starts reading files in that directory」；
  规模上限「files over 200 lines consume more context and reduce instruction adherence」；
  硬约束「**Hard stops belong in settings.json permissions, a linter, or a pre-commit hook.** A markdown file in the prompt is the wrong place for rules that cannot tolerate exceptions」；
  可观测「Run `/memory` to verify what actually loaded — **failures here are silent**」。
  （[Claude Code 文档](https://code.claude.com/docs/en/memory)，整理文 [HackerNoon 2026-03-30](https://hackernoon.com/navigating-claude-code-claudemd-done-right)）
- AGENTS.md 标准：「The **closest** `AGENTS.md` to the file being edited takes effect」，「walks up the directory tree and reads the **nearest** AGENTS.md」，
  OpenAI 主仓曾有 88 个 AGENTS.md。（[monorepos 指南](https://mintlify.wiki/agentsmd/agents.md/guides/monorepos)、[Codex 兼容页](https://mintlify.wiki/agentsmd/agents.md/compatibility/codex)）
- Gemini CLI：全局 + 「searches for a `GEMINI.md` file in your current working directory and then in each parent directory **up to the project root (identified by a `.git` folder)**」+「also scans for `GEMINI.md` files in **subdirectories**」；
  `/memory show` 打印拼接后的全文；文件名可配（`context.fileName` 能塞 `AGENTS.md`）。
  （[官方文档](https://google-gemini.github.io/gemini-cli/docs/cli/gemini-md.html)）
- Cursor：`.mdc` + frontmatter（`description` / `globs` / `alwaysApply`）产生四类规则：总是、按 glob、按模型判断、手动。
  （[规则说明](https://docs.arantic.com/cursor/rules)、[.mdc 指南](https://continuumcode.ai/guides/cursor-rules)）

## 三、对本仓的判定

1. **DSH 的边界比 Claude Code 窄一层**：无 `.git` 时 `projectRoot = cwd`，父目录的 `AGENTS.md` 不注入。
   Gemini 同样以 `.git` 为界，但它额外**扫子目录**；Claude Code 根本不用 `.git`。
   ⇒ 想让"目录里写了就生效"，要么在该目录开会话，要么让"含 `AGENTS.md` 的目录"本身成为项目根。
2. **"任务域"不是目录属性。** `remote-exec`（命令要离开本机）跨越任意目录，按目录注入天生错配。
   社区对应物：Claude Code 的 skills（frontmatter 决定何时命中）+ hooks（确定性拦截）。
3. **可观测性才是"静默失败"的解药。** 四家里两家提供 `/memory` 一类入口，作者原话是"failures here are silent"。
   本仓没有等价物 ⇒ 规则没生效时没人知道。
4. **md 里写不出"必须"。** 博客里那句是本条的根据：不容忍例外的规则不能放在提示词文件里。
   ⇒ 判据能在代码里表达的，一律下沉 L3；md 只留"需要人判断"的约定。

## 四、据此的三条做法

1. **载体对位**：任务型规则进 **L2 技能**（catalog 里写清触发词：ssh / scp / schtasks / 远端 `.ps1`），目录型约定才留 L1。
2. **硬判据下沉 L3**：能写成 `if` 的（`.ps1` 含非 ASCII、`scp … && … sc create` 串联）进守卫 deny，不留在 md。
3. **加可观测入口**：一条命令复刻发现规则，打印"项目根 + 本次会注入的指令文件清单 + 字节数"，让"没生效"当场可见。
