# 跨机执行场景规则

> 本层只在"命令要送到另一台主机去跑"时生效。与 L0 冲突时，**本文件优先**（越具体越优先）。
> 只写这个域特有的东西；通用纪律（先测再断言、先方案再动手）不要抄过来。

1. **每步自己带落地证据，不用 `&&` 传递信任** —— 源在本机 `test -f`、目标在对端
   `ssh <主机> 'test -f <真实路径>'`、下游消费点再核一次（服务注册后读 `sc qc` 的
   `BINARY_PATH_NAME`，进程看映像路径）。任一步失败立即单独报错退出，不串联。
2. **完成判据不得出现在被检文件里** —— 动手前 `grep -c '<TOKEN>' <被检脚本>` 必须为 0；
   跑完用外部量四条收口（退出码 + 产物存在 + 产物 mtime 晚于脚本 + 内容命中）。
   报错回显会把源码原样吐出，写进源码的判据等于没有判据。
3. **对端脚本正文只用 ASCII** —— Windows PowerShell 5.1 读无 BOM 文件时按 ANSI 代码页解码，
   中文多字节会与相邻字节粘连，表现为"语法错但那一行看着没问题"。要中文就 UTF-8 BOM 或 `pwsh 7`。
4. **先核现场再动手** —— 路径、服务状态、目标目录都在对端当场读一次
   （`sc query` / `test -d`），不沿用上一次会话的结论；对端回显里"成功"两个字不算证据。
