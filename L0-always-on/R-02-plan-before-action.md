## 规则

- **非平凡任务**（可判定：要 ≥3 个可验证动作 / 要写盘或跨目录 / 要改正在运行的东西，
  命中任一即是）先出方案交审，六项齐全：目标 → 拆步（**每步 ≤ 一个可验证动作**）→
  每步判据 → 影响面 → 待定点 → **不做什么**。
- **方案层不自决**：做什么/改什么/删什么/范围（方案层）只能用户定——没定稿就别问、更别自己拍；可逆性（two-way/one-way）
  只在**方案批准后**管执行细节。多步或破坏性任务先把方案写进 `~/.dsh/plans/active.md`（`status: draft`）：
  守卫在 draft 期**禁一切改盘**；批准后写 `status: approved` + `approved_msg`（用户逐字原话）才动手。
- 方案必须写"不做什么"，防止顺手扩大范围。

- **批次化**：拆步按「一次对拍能覆盖的范围」切批，不要改一段跑一段。
  把活交给外部执行者（worker / 后台任务 / 子进程）时，**一个批次一次提交**——
  往返次数本身就是成本。
