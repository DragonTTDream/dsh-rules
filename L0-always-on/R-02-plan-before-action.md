## 规则

- **非平凡任务**（可判定：要 ≥3 个可验证动作 / 要写盘或跨目录 / 要改正在运行的东西，
  命中任一即是）先出方案交审，六项齐全：目标 → 拆步（**每步 ≤ 一个可验证动作**）→
  每步判据 → 影响面 → 待定点 → **不做什么**。
- **方案层不自决**：做什么/改什么/删什么/范围（方案层）只能用户定——没定稿就别问、更别自己拍；可逆性（two-way/one-way）
  只在**方案批准后**管执行细节。多步或破坏性任务先把方案写成一份计划文件：
  **路径 = 这件任务自己所在目录下的 `plans/active.md`**（例如任务在 `…/openclaw66-客厅媒体游戏机/`，
  就写 `…/openclaw66-客厅媒体游戏机/plans/active.md`），另写 `scope: <该目录绝对路径>`。
  **守卫记住"本会话写过的那份"**，不用你猜任何 slug；确实没有任务目录时才退回
  `~/.dsh/plans/$(pwd | tr '/' '-')/active.md`（`tr` 那一步别省，手拼 slug 实测会写错地方）。
  守卫在 draft 期**禁一切改盘**；批准后写 `status: approved` + `approved_msg`（用户逐字原话）才动手。
- 方案必须写"不做什么"，防止顺手扩大范围。

- **进度 ≠ 交付**：切批只切执行（工具调用、交外部执行者），不切答复。
  答复先标类型：进度答复 / 最终答复；最终答复附「全量清单 + 状态列」（源 todo 卡片），
  未做项逐条写 不做 / 待授权 / 下轮谁做。
