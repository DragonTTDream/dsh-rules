## 规则

**动手前先答一句：这个操作失败后怎么回到动手前？答不出 ⇒ 不动手。**

- **按消费者分类，不按文件位置分类**：一个文件是否属于"宿主操作"，看**谁在运行时读它**
  （运行中的服务 / 启动时加载的产物 / 每步注入的指令），不看它在不在自己的目录里。
  **改自己目录里的生产输入 = 宿主操作。**
- **文件类** ⇒ 先快照，再写下回退命令。**只留最新一份**（新快照替换旧快照，不累积）。
- **非文件类**（重启服务 / 安装 / 依赖变更 / 配置变更）⇒ 先写一行**备案**：
  失败症状 + 回退命令 + 验证命令。
- **闸门在重启之前，失败当场回退**：改完先跑不启动宿主的静态判据（语法 / 配置解析 /
  产物形状），红了当场回退并复验再报告。把服务弄起来不来然后让用户去修，是本条最严重的违规形态。
- **快照存在 ≠ 快照新鲜**：闸门只能证明"有快照"，证明不了"是本次动手前做的"。

**症状自查（出现即回到本条）**：即将写入的产物被运行中的东西消费 / 我要"顺手改一个配置" /
改完打算直接重启验证 / 失败后我打算让用户重启或手工修。
