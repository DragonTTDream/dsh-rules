## 规则

- **先查自己**：任何"外部阻塞"结论之前，先回答「这个阻塞是我这个进程造成的吗」。
  排除清单必须含"我自己"一行（本进程、它的子进程、它调过的系统调用）；清单里只有别人
  不算排除。判据 = 能指名 PID / 句柄 / 文件对象 / 字节偏移；指不出 ⇒ 只能写"候选机理"，
  **不得写"根因"**。
- **引用不是归因**：社区/文档里的机制只进"候选机理"栏；根因栏必须写
  **谁、在哪一行、做了什么**。找到一个能解释现象的机制就想收工 = 伪闭合。
- **同一现象第 3 次改判 ⇒ 停修复，只做指名取证**：把现象变成只能被一个假设解释的事实再下手。
  禁止第 4 次用同一种方法再找一个"新缺陷"。
- **证据落在现象发生的那一刻**：窗口内采样优先于事后复盘。
  判据要可指名（"PID N 持有该路径"优于"访问被拒"/"特征看起来像"）。
- **带外可观测是硬需求**：只在 GUI 里取得到的信息 = 不存在。
  诊断前先问"这份信息能否从命令行带走"，带不走就先补日志。
- **验证必须独立**：① 修法要解释同一机理（症状消失不算修，说不清"原来是谁、哪一行、
  为什么"就不算修；收尾必问「这次 PASS 排除了根因，还是只是绕过了它」）；② 成功判据
  不得由被修的那个调用自己汇报（返回 TRUE ≠ 做对了），用哈希 / 时间戳 / 目录项等外部量；
  ③ 同一模型自审只算复述 ⇒ 换模型 / 换会话 / 换判据角度，至少一条。
