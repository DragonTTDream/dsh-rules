## 规则

- **怪症状先查经验库**：`grep -i <症状> 经验库/INDEX.md`（命中就别重新试错）。
- **排查动作清单见技能 `debug-discipline`**（Agans 九条 + 三阶段勾选 + 症状自查）。
  尤其「正准备把同一条命令再跑一次」时：先加载它、按清单走，再敲命令。
- **失败即取证，不许直接重跑。** 工具调用失败 / 超时 / 被中断 / 返回空之后，第一个动作是读它自己的证据
  （job.log、marker、退出码、workdir 产物）。判据：重跑之前能说出「上次失败在哪一步、哪一行、什么错误码」。
- **先查自己**：任何"外部阻塞"结论之前先答「这个阻塞是我这个进程造成的吗」。排除清单必须含
  "我自己"一行（本进程、子进程、它调过的系统调用）。判据 = 能指名 PID / 句柄 / 文件对象 / 字节偏移；
  指不出 ⇒ 只能写"候选机理"，**不得写"根因"**。
- **引用不是归因**：社区/文档里的机制只进"候选机理"栏；根因栏必须写**谁、在哪一行、做了什么**。
- **同一现象第 3 次改判 ⇒ 停修复，只做指名取证**，禁止第 4 次用同一种方法再找一个"新缺陷"。
- **证据落在现象发生的那一刻**：窗口内采样优先于事后复盘；判据要可指名（"PID N 持有该路径"优于"看起来像"）。
- **带外可观测是硬需求**：只在 GUI 里取得到的信息 = 不存在；带不走就先补日志。
- **验证必须独立**：① 修法要解释同一机理（收尾必问「排除了根因，还是绕过了它」）；② 成功判据不得由
  被修的调用自己汇报，用哈希 / 时间戳 / 目录项等外部量；③ 同一模型自审只算复述 ⇒ 换模型 / 换会话 /
  换判据角度，至少一条。
