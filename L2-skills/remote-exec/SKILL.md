# 跨机执行

> 本技能只在"命令要离开本机"时加载。跨机出错在本机看不见，四条按顺序执行。

## 1 每步自己带落地证据，不用 `&&` 传信任

`&&` 只传退出码，不传"实物到位"：上游失败 ⇒ 下游整段静默跳过，而下游的成功回显会被当成"上游也成了"。

```bash
[ -f "$SRC" ] || { echo "SRC MISSING: $SRC"; exit 1; }
scp "$SRC" "$HOST:$DST" || { echo "SCP FAILED rc=$?"; exit 1; }
ssh "$HOST" "test -f '$DST'" || { echo "DST MISSING: $DST"; exit 1; }
ssh "$HOST" "<注册或启动>" || { echo "REGISTER FAILED"; exit 1; }
```

注册后还要读回它**实际引用的路径**（`sc qc <服务名>` 的 `BINARY_PATH_NAME`）：非空且等于 `$DST` 才算成。

## 2 完成判据不得出现在被检文件里

报错回显会把源码原样吐出，写进源码的判据等于没有判据。

- 动手前 `grep -c '<TOKEN>' <被检文件>` 必须为 0；不为 0 ⇒ 换一个不写进被检对象的 token。
- 收口用外部量四条：退出码 0 + 产物存在 + 产物 mtime 晚于脚本 + 产物内容命中。
- 判据与被检对象不得共用同一条通道（同一个 stdout / 同一个文件）。

## 3 对端脚本正文 ASCII-only

PowerShell 5.1 读无 BOM 文件时按系统 ANSI 码页解码（中文 Windows = GBK），UTF-8 中文会与相邻字节粘连，表现为"语法错但那一行看着完全没问题"、脚本根本没跑起来。要中文就 UTF-8 BOM，或改用 `pwsh 7+`。

## 4 先核现场再动手

路径、服务状态、目标目录都在对端当场读一次（`sc query` / `test -d`），不沿用上一次会话的结论。

## 坑

- `ls <目录>` 存在 ≠ 文件到了：用 `test -f <确切文件>`。
- `bash -n` 通过只证明语法完整，不证明脚本能跑。
- 只看整条链的最终退出码 = 看的是**第一个失败步**，不是最后一步。

细节与反例见经验库三条：链式短路 / 判据被污染 / 脚本被错误解码（`dsh-rules/经验库/`）。
