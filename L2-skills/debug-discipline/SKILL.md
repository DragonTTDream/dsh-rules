# 排查期动作清单

> 原则见 **R-14**（排障先排除自己）。本技能只做一件事：把原则拆成**按顺序可勾**的动作。
> 依据：David Agans《Debugging: The 9 Indispensable Rules》(2002)；本机 2026-10-21 一次
> 六批次的复盘（同一把文件锁被追了 6 批、起了 5 个编号）。

## 九条（Agans 原序，每条一句判据）

1. **先理解系统** —— 能不能画出这条路径上"谁在什么时候读这个资源"？画不出就先读代码，别先猜。
2. **让它稳定复现** —— 复现不了一律不动手。判据：一条命令 + 一个观察点，能重复出同一现象。
3. **停止推理，去看** —— 判据：结论背后有一个**当场采到的读数**，不是一段解释。
4. **分而治之** —— 每次把可能范围砍一半。禁止"再找一个新的可能原因"。
5. **一次只改一个变量** —— 且改的是**验证机理**的变量，不是"绕开现象"的变量。
6. **留审计轨迹** —— 一个现象**只给一个编号**。同一现象起第二个名字，会把"没进展"伪装成"推进中"。
7. **先检查插头** —— 先查最基础、最容易被跳过的那项：它到底有没有在跑？谁最常被跳过 —— **我自己的进程**。
8. **换个新鲜视角** —— 同一模型自审只算复述。换模型 / 换会话 / 换判据角度，至少一条。
9. **没修好就是没修** —— 判据：修完能一句话说清"原来是谁、哪一行、为什么"。说不清 = 没修。

## 三阶段勾选（写规格 → 跑闸门 → 收尾）

### 写规格 / 设计阶段

- [ ] **判据可指名？** 能到 PID / 句柄 / 文件对象 / 字节偏移，而不是"访问被拒""看起来被占用"。
- [ ] **平台常量有官方出处？** Win32 常量、错误码、标志位必须对官方表核；并且**必须有钉死值的单测**。
- [ ] **失败路径的日志能带外读？** 写清具体错误码，不许只写"失败"。只在 GUI 里看得见的日志 = 不存在。
- [ ] **写和审不同源？** 规格、实现、审查、闸门是不是同一个模型同一种直觉？

### 跑闸门之前

- [ ] **源码层闸门在？** 编译 / vet / 单测全绿**拦不住平台语义 bug**（`errno == nil`、`0x10` 这类）。
- [ ] **目标平台与构建标签写进命令**，不靠记忆。

### 收尾必答

- [ ] 这次 PASS 排除的是**根因**，还是只是**绕过了它**？
- [ ] 探测脚本 / 中间日志已归档或清理（R-11）。

## 症状自查（出现即回到本技能）

> "引用了一个机制就收工" · "排除清单里全是别人" · "同一个锁已经有两个编号" ·
> "批次验收 PASS 但症状还在" · "这个数字我记不清是哪轮读的"
