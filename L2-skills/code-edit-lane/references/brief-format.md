# brief 格式（六项，机械可检）

**何时读它**：写 `<批次>-brief.md` 时；提交 worker 前跑形状检查时。

brief 只回答一个问题：**改哪里**。它不含需求（需求在 `spec/<批次>.md`），也不含成段代码（代码在取证产物与上游仓库）。
理由：让 worker 自己翻目录定位，那笔探索会原封不动地进它的上下文，而且改错地方的概率更高。

## 六项（标题逐字，供 grep 计数）

```
## 1 改哪里（文件:行）
## 2 签名与常量
## 3 依赖真源（去哪读哪几行）
## 4 可抄参考
## 5 禁改清单
## 6 闸门命令与预期输出
```

| 项 | 写什么 | 判据 |
|---|---|---|
| 1 | 每处改动一行：`路径/文件.go:120-168` + 一句话说改什么 | 每条都带行号区间 |
| 2 | 被改函数/类型的现有签名；必须原样保留的常量值 | 签名逐字可搜到 |
| 3 | 只给路径 + 行区间，**不贴内容**（worker 自己按区间读） | 不出现成段代码 |
| 4 | 上游等价实现的位置（路径 / commit / URL），允许抄 | 至少一条 |
| 5 | 不许动的文件、函数、依赖，每条带一句理由 | 理由必写，没理由的禁令会被绕过 |
| 6 | **一条**对拍命令逐字 + 预期输出形状（如"退出码 0 且无输出"） | 命令可直接复制执行 |

## 形状检查（提交前跑，红则不提交）

```bash
b=<批次>-brief.md
n=$(grep -c '^## [1-6] ' "$b")
L=$(grep -oE '[A-Za-z0-9_./-]+:[0-9]+' "$b" | wc -l)
[ "$n" -eq 6 ] && [ "$L" -ge 3 ] && [ "$(stat -c%s "$b")" -le 4096 ] \
  && echo BRIEF-OK || echo "BRIEF-FAIL n=$n refs=$L bytes=$(stat -c%s "$b")"
```

三条都是硬数值：六节齐全、至少三处 `文件:行`、体积 ≤4 KiB。超体积基本等于在抄内容 —— 该搬回取证产物。
`refs` 用 `grep -o` 数**出现次数**，不用 `grep -c`（后者数行，一行两个区间只算一个）；阈值定 3 而不是定高，是为了不逼着往 brief 里灌凑数的行号。

## 为什么必须机械可检

"该写 brief"是意图，"跑一条命令看到 `BRIEF-OK`"才是生效点。纪律没有机械判据时，是否执行无法判定，也就无法说它被违反了。
