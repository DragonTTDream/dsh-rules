# 代码编辑 lane（上下文隔离的离线窗口）

## 必守八条（违反即失去隔离或拿到假结果）

1. **代码不进主上下文。** 主对话只写规格、提交、读结论行；worker 的日志与 diff 不整篇读进来（要查就 grep 取所需行）。
2. **闸门是外部对拍，不信 agent 收尾。** worker 自称"全部通过"不算证据——必须跑一个它没参与的构建/测试/比对命令；红了当场回退并复验，再报告。
3. **分流按「目标模型 vs 当前已装载」判定，不按「任务重不重」——但两条都经 `arbitrate_run` 提交：**
   - 目标模型 == 当前已装载 ⇒ `arbitrate_run(unload=false, warm=false)`：**不卸**（零成本），但**照样持有回合**等到 marker 到手；
   - 目标模型 != 当前已装载 ⇒ `arbitrate_run(unload=true, warm=true)`：先卸，跑完把主模型装回并预热；
   - 无模型重活（编译 / 下载 / 转写）⇒ `arbitrate_run(unload=true, warm=true)`：先卸，为内存让路。
   - **禁止用后台 job 提交 worker**（`run_in_background` / `&` / 前台超时被转后台）：工具一返回主会话就继续生成，**和 worker 抢同一条推理序列**——实测真实发生过（7 个窗口里 4 个），代价是每条插入请求都要把整段前缀重算一遍。
   - 跑前**读一次端点状态**：`ttl` 会在空闲时自动卸载，"在不在"必须当场问，不能假设。
4. **层间只传文件。** 规格落盘 → worker 读规格 → 结果落盘 → 闸门读产物。不靠对话传递需求。
5. **提交前必须有 brief（位置）。** 规格只说"要什么行为"；worker 自己翻目录定位，既撑大它的上下文，又更容易改错地方。把位置写进 `<批次>-brief.md`（六项 + 机械形状检查，见 `references/brief-format.md`，**写 brief 时读它**）。三件套各管一件事：`spec` 管行为、`brief` 管位置、`prompt` 只指路（不重复规格）。

6. **规格是最大的错误源头，规格要先过闸。** spec 里凡出现平台常量 / 错误码 / 标志位（Win32、errno、协议字段），必须附**官方表出处**，并在同批次写一条**钉死该值**的单测；判据必须可指名（PID / 句柄 / 目录项 / 时间戳），不许写"访问被拒"这类能被多个假设解释的签名。理由：worker 会**忠实实现**规格里的错误，审查也跟着错——`0x10` 被当成 `REPLACE_EXISTING` 写进 spec，实现、审查、Linux 侧闸门**全绿**。
7. **失败必须落在可带外读的地方。** worker 的失败路径写文件日志 + 具体错误码；只在 GUI 里看得见的日志等于不存在。
8. **同一现象第 3 次改判 ⇒ 停 lane。** 不再开新批次、不许"再找一个新缺陷"，转指名取证（见技能 `debug-discipline`）。

## 选哪个 worker（接口越窄，弱模型越不容易跑偏）

| 变体 | 工具面 | 用在 |
|---|---|---|
| `clone-worker` | edit/read/grep/glob/list/bash + 联网 | 需要取上游源码的复刻批次（**默认**） |
| `clone-offline` | 同上但**断网**、不出工作台 | 不需要联网的批次 —— 少一次试探就少一轮上下文重算 |
| `clone-scout` | read/grep/glob，**不能写** | 只读取证：定位、比对、写 brief 素材（把"读一堆"的成本挪出主对话） |

判据：需要联网吗 → 不需要就 `clone-offline`；只需结论不需改码 → `clone-scout`。
依据：SWE-agent 的 ACI —— **接口设计本身决定 agent 表现**，窄接口少试错。

## 何时用（有固定开销，别拿小任务试）

每次调用都要付**固定开销**：找路 + 写规格 + 交接 + 闸门——比一次小改动本身贵得多。

- **该用**：主会话要消化的代码/日志量**远大于**这笔开销（多文件改动、长 diff、反复编译-测试循环），或需要**可重跑规格 + 外部闸门**。
- **不该用**：小任务、一次写成、无对拍需求 —— 直接自己写更快更准。
- 两臂实测数字见工作区档（不写进技能）。

## 动作顺序

1. 写规格 —— **一个规格 = 一个批次**：把"一次对拍能覆盖的全部改动"一次写进去（多个文件、多个功能一起），并给**一条**对拍命令；同一批次一并写 brief（必守 5），两份一起落盘。往返次数就是成本，不要改一段跑一段。
2. 提交 worker —— **经 `arbitrate_run` 提交**（它持有回合，主会话在此期间一帧都不生成）。这是**离线窗口**：worker 在自己的循环里把闸门跑绿再退出（规格里写明允许它迭代几次）；主会话只等，**不中途插话、不"趁等待做点别的"**（插进去就是抢前缀，等于把 worker 的算力拆走）。
   - **提交前**必须把**进度页地址（本机 + 局域网两条）**发到对话里 —— 工具持有回合直到 marker，窗口内推送做不到，**提交后补发等于没发**。地址与起停方式查工作区档「观察件」行。
   - **闸门提交不需要**：闸门是编译/测试，没有 agent 循环，没有可看的进度。
3. 只读 marker 与结论行：`marker=ok` 就走闸门。闸门红了**别自己拼重试 prompt**，跑
   `bin/retry-spec.sh <批次> <原prompt>` —— 它把失败行 + 日志尾部 40 行 + 硬约束拼成
   `spec/<批次>-retry.md`。判据：重试 prompt 里必须有上一次的**具体失败行**（`文件:行` + 错误码），
   不许出现"再试一次"。同一改法连续失败两次 ⇒ 换假设，第三次不许重试。
4. 跑外部闸门。绿了才算完成；红了回退并复验。**收尾记成本**：
   `bin/cost-log.sh <批次> <session-id>` → `out/cost.tsv`（input / output / cache_read / wall）。
   三个要看的数：**cache_read 命中率**（前缀复用效果，实测有会话到 90%）、
   **input 总量**（探索步数）、**wall**（体感）。没有这张表，任何"优化"都无法验证。
5. 收尾必答一句：**这次 PASS 排除的是根因，还是只是绕过了它？** 说不清"原来是谁、哪一行、
   为什么" = 没修好（Agans 第 9 条：if you didn't fix it, it ain't fixed）。

## 判据

- worker 写出 `marker=ok`（脚本必须成功失败都写 marker）。
- 外部闸门退出码为 0。
- 修复类批次另加一条：能用一句话说出"原来是谁、在哪一行、为什么"——说不清就只是绕过了症状。

## 坑（每条都真实发生过）

- **每批都是新会话 ⇒ 前缀缓存不跨批复用**（`POST /api/session` 建新会话）。会话内靠
  `systemPromptUpdate: in-history` 把每步压到 2.1 s，但批与批之间那张前缀要重付一次。
  实测单会话累计 input 2.0–2.4M token ⇒ **"减少步数"比"复用前缀"更值钱**。
- **marker 读不到**：任务脚本若把 stdout 重定向走，调用方就永远等不到 marker，只能干等到超时。
- **主对话与 worker 同时跑**：推理服务一次只答一条序列；两条对话交替 = 每次切换都要把对方的整段前缀重算一遍（算力被拆）。**实测发生过**：后台 job 提交 ⇒ 工具立刻返回 ⇒ 主会话继续生成。所以提交必须持有回合。
- **卸载了没装回**：只有 `arbitrate_run` 有"跑完装回 + 预热"的四层兜底。分流判错，用户下一条消息就要等一次冷启动。
- **"完成"是自述**：没跑闸门就汇报，等于把 harness 的自信当证据（对照里出现过"宣布全部完成"而测试是红的）。
- **"给了闸门结果却说不出进度"**：闸门窗口里没有 worker，`opencode.db` 不会新增会话 —— 判据是 db 的 `session` 表最新时间戳。别把闸门窗口说成"跑了 lane"，也别在闸门窗口里找进度页（2026-10-16 真实发生过：主会话自己写代码 + 只提交闸门，用户问"为什么没给我地址"）。
- **自召回的预热是会话绑定的**：会话跑的若不是本地模型，预热本地模型是白装——插件按当前会话路由决定预热，不要手动绕开。

## 工具与指针

- 排查期清单：技能 `debug-discipline`（Agans 九条 + 三阶段勾选，含"先检查插头 = 先查我自己"）。
- `scripts/lane-run.sh` → 提交 worker（需要 `CODE_LANE_BENCH` 指向工作台目录）。
- `scripts/lane-check.sh` → 转发外部对拍闸门（无模型参与）。
- 工作台的位置、端点、模型名、worker 角色、卸载方式：**查工作区档的「入口速查」表**——照上面写好的命令直接跑，**不要自己去翻目录、读 PLAN.md 或脚本**（本机实测：那笔探索就是最贵的固定开销）。
