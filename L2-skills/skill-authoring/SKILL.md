# 技能写作标准

> 依据：[Anthropic best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)（全文镜像与本机实测见 `Harnessworks/agent-rules-tuning/skill-标准-2026-10-14.md`）。

## 1. 硬约束（违反即失效）

- `name` ≤64 字符，小写字母/数字/连字符，等于目录名。
- `description` ≤1024 字符，**第三人称**，先写做什么、后写何时用。与 `whenToUse` 合并 ≤1,536 字符。
- **YAML 写坏了不报错**：元数据变空 → 技能永不触发。改完必核对技能目录里是否出现该技能。
- description 要"推"一点：模型倾向少触发。写「用户提到 X / Y / Z 时就用」，别只写「关于 X」。

## 2. 三层加载预算

| 层 | 何时在场 | 预算 |
|---|---|---|
| 元数据 | **每个请求** | ~200 tok |
| 正文 | 触发时加载，**加载一次，压缩后只留开头** | <500 行、**<1,500 tok** |
| `scripts/` `references/` `assets/` | 按需读 | 无上限 |

技能目录整体只占上下文约 1%，**溢出时先丢最少调用的 description**。必守规则放正文最前。

## 3. 正文只写纪律

默认假设：**模型已经很聪明**。每段问：它不知道吗？能假设它知道吗？这段对得起 token 吗？

**禁写清单**（命中就移出正文）：

| 不写 | 去处 |
|---|---|
| 本机事实（端口/路径/服务/版本号） | 对应工作区的档 |
| 迭代日志、会话日志、变更历史 | `git log` |
| 调研引用与合并说明 | `agent-rules-tuning/merge-*.md` |
| 一次性实测矩阵、论证性内容（"证明这不是偶发"） | 领域档；技能只留结论一句 |
| 未实现的机制判据、时间敏感信息（"目前"、"截至"） | 立项档 / 领域档 |

只留：**触发条件、动作顺序、判据、坑（一句话 + 为什么）**。

## 4. 写法

- 祈使句。解释**为什么** —— 全大写 MUST/ALWAYS/NEVER 是黄旗，模型理解理由才能推广到没写到的情形。
- 给默认 + 逃生口，别列一堆并列选项。术语全文一致。具体例子优于描述。
- 按脆弱度定具体度：多种都行 → 文字指引；有偏好模式 → 伪码/参数；脆弱且要求一致 → 精确命令。

## 5. 分层

目录形态：`SKILL.md`（概览 + 导航 + 必守规则）+ `scripts/`（确定性动作，可执行而不读入）+ `references/`（细节，按需读）+ `assets/`（模板/字体）。

参考文件离正文**一层深**，写明"何时读它"；>100 行加目录。多领域按变体拆文件，只读需要的那份。

## 6. 质量清单（改完逐条过）

- [ ] description 具体、含关键词、做什么在前
- [ ] 必守规则在正文最前；正文 <500 行、<1,500 tok
- [ ] 无本机事实 / 日志 / 调研引用 / 时间敏感内容
- [ ] 术语一致，无全大写堆叠，有具体例子
- [ ] 引用一层深，>100 行的有目录
- [ ] 核对技能目录里出现该技能（YAML 坏了不报错）

## 7. 版本控制

`~/.dsh/skills` 已是 git 仓库。**不建 `backups/`，不算 SHA256SUMS** —— 复制全文是仪式，git 有全部历史与 diff。每次改动一个 commit，message 写清改了什么、依据什么。

```bash
git -C ~/.dsh/skills log --oneline                              # 历史
git -C ~/.dsh/skills checkout HEAD~1 -- <name>/SKILL.md         # 回滚
```
