# vision-forward — 视觉带外转发

界面允许发图，但主模型是纯文本量化档，看不了图。这个插件把图**改道**：
换成文字再交给主模型，主模型自始至终没收到过图片。

## 注入点

```js
export const inject = ["tools", "llm", "attachments", "sessionProjections"];
```

四个钩子缺一不可：

| 钩子 | 用来干什么 |
|---|---|
| `tools` | 注册 `vision` 工具（会话内主动看图） |
| `llm` | 在 `llm/stream` 上把请求改道到孪生条目 |
| `attachments` | 识别消息里的图片块 |
| `sessionProjections` | 会话投影里补图的状态 |

## 两条通道

| 通道 | 用哪个模型 | 什么时候用 |
|---|---|---|
| **逐字转录**（默认） | OCR 模型，2–3 GB，亚秒级 | 截图、界面文字、报错信息 |
| **视觉推理**（升级） | 视觉模型，15 GB 级 | 图表读数、GUI 元素定位、空间关系 |

选择由 `vision` 工具的参数决定；`mode=ocr` 走前面那条，`mode=understand` 走后面那条。

## 执行顺序（顺序错了就是事故）

```
卸主模型 → 装 OCR/视觉模型 → 出结果 → 卸视觉模型 → 装回主模型并预热 → 把图块换成文本 → 短路返回
```

主模型必须在视觉模型之前离场，否则同时在场会 OOM。
回归预热的耗时吃在工具调用里（本机实测：视觉调用 2.6 s + 装回主模型 ~42 s）。

## 失效症状

| 症状 | 原因 | 处置 |
|---|---|---|
| 主模型直接 404 / 502 | 孪生别名被直通到真模型（必须改道） | 检查 `twinModel` 与 `mainModel` 的映射 |
| 转录结果为空，content 是空的 | 思考链吃满 `maxTokens` | 调大 `maxTokens`（本机从 2048 调到 8192） |
| `replace: true` 后图不见了 | 图必须活到 `llm/stream` 才会被转录 | `replace` 保持 false |
| 原生识图的会话也被调了 `vision` 工具 | 白花钱（图本来就进上下文） | 把该模型加进 `nativeVisionModels` |
| 显存不够、装载失败 | 主模型还没卸完 | 调 `vramWaitMs` / `vramFreeTargetMB` |

## 恢复配方

```bash
# 禁用（最轻）
#   条目加 disabled: true + 重启宿主
#   注意：禁用后孪生条目必须一并注释掉，否则它只是模型表里不存在的 id，选中必 502
# 彻底回退
#   删 insert 段 + 删孪生模型条目 + 重启宿主
```

## 已知边界

- 它不改主模型的 `input` 声明（真主模型仍是纯文本）。改道靠的是孪生条目。
- 一次一张，不批量刷。批量识图会把离线窗口开合几十次，装载成本比收益大。
