# L4 · 自制插件

这三个是本机**自己写的**插件（不是社区插件，也不含对别人代码打的补丁）。
区别只在角色：一个守纪律，两个给能力。

| 插件 | 角色 | 注入点 | 对外提供 | 代码 | 收录 |
|---|---|---|---|---|---|
| `tool-guard` | **守卫**（模型绕不过） | `["tools"]` | 无（只在执行前拦） | 52K | ✅ [`../L3-guards/tool-guard/`](../L3-guards/tool-guard/) |
| `self-recall` | 能力：保活 + 资源仲裁 | `["tools"]` | `arbitrate_run` / `arbitrate_warm` / `arbitrate_status` | 92K | ✅ [`self-recall/`](self-recall/) |
| `vision-forward` | 能力：视觉带外转发 | `["tools","llm","attachments","sessionProjections"]` | `vision` | 72K | ✅ [`vision-forward/`](vision-forward/) |

## 为什么 `tool-guard` 不在这个目录

它在 `L3-guards/`，因为它是**强制层**——和 L0–L2 那些"模型可违反"的层不是一回事。
本目录只放**能力型**插件：它们扩展能做的事，不强制不该做的事。

## 每个插件都该有的四项（缺一项就等于没有文档）

1. **失效症状**——坏了的时候看起来是什么样，不读代码也能判断。
2. **配置键**——它认哪些键，哪些是必填。
3. **恢复配方**——禁用/回退的最小动作。
4. **依赖声明**——它假设宿主存在什么（`ctx.tools`、`llm/stream` 钩子等）。

三份 README 都按这四项写。

## 本地与原位的区别

`index.js` 是从本机逐字拷来的，**只改了一处**：`endpoint` 默认值改成空字符串
（本机事实不进公开仓，由 `config.example.yml` 提供占位符）。

所以本目录的代码可以直接覆盖回本机，行为不变——前提是你把配置带上。

## 版本

三个目录在原位都不是 git 仓库（2026-10-21 记录）。本仓里它们是版本化的；
**真正的版本权威是运行中的那份 + `~/.dsh/snapshots/latest` 的单槽快照**。
两边不一致时，以"谁先改"为准，不要凭记忆判断。
