# 按文件类型自动附加规则（Auto Attached）——可行性结论

> 状态：**只做了可行性确认，未写代码**。结论见最后一节。
> 起因：Cursor 的 rules 有四种触发型（Always / Auto Attached / Agent Requested / Manual），
> 本仓的 L0/L1/L2/`/命令` 正好对应后三种 + Always，**缺 Auto Attached 那一格**。

## 1. 本机现在能做到哪一级

DSH 的 `dsh-agent-instructions` 只认固定文件名（`AGENTS.md` / `CLAUDE.md`，加 `.local` 覆盖），
但它的发现逻辑是**两层**的：

| 层 | 机制 | 效果 |
|---|---|---|
| 祖先链 | 从项目根到 cwd 逐级找 | 目录级附加（越深越具体、越优先） |
| **后代目录** | 模型**碰到某文件**时，把它与 cwd 之间经过的目录里的指令文件也拉进来 | **这就是"按位置自动附加"**——把 `AGENTS.md` 放到代码树那一层，改那里的文件就自动带上 |

所以**按目录的 Auto Attached 已经原生可用**，只差"按扩展名跨目录"这一级。

## 2. 按扩展名跨目录：技术上可行，但有代价

钩子存在且已在用：

- `dsh-agent-instructions` 自己就是 `ctx.on("agent/pre-step")` + `inject: ["sessionProjections"]`
  （`lib/index.js:1073,1271`）。插件可以在同一个事件上追加内容。
- 要"知道碰了哪些文件"，可像 `tool-guard` 那样挂 `tools/pre-execute` 记录路径，再在
  `agent/pre-step` 里按 glob 附件规则。

**代价（这条比可行性更重要）**：

本机的每一步延迟已经压到 **2.1 s**，靠的是「前缀字节稳定」——
`systemPromptUpdate: in-history` + pi-ai 前缀缓存补丁（cacheRead 0 → 107,435）。
动态注入只有两种落法：

| 落法 | 对前缀缓存 | 结论 |
|---|---|---|
| 改写消息 0 / 系统提示 | **整段前缀失效**，每步回到 prefill 全量（曾实测 56.7 s/步） | 不可接受 |
| 追加新消息（in-history） | 前缀保住，但每步多付新增 token | 可接受，但只在规则集**很大**时才划算 |

而规则集如果只是几条 Go 约定（几十 token），**追加的收益低于它的成本**。

## 3. 结论

| 需求 | 现在怎么办 | 要不要写插件 |
|---|---|---|
| 改 `.go` 文件时自动带 Go 规则 | 在代码树那一层放 `AGENTS.md`（原生后代目录发现） | **不用** |
| 改 `.ps1` / `.go` 各自带不同规则，且这些文件散在任意目录 | 需要按扩展名的动态注入 | **要做，但先证明规则集足够大** |

建议顺序：先按原生方式落地（模板见 [`../../L1-scoped/examples/by-language.md`](../../L1-scoped/examples/by-language.md)），
**等真的出现"同一批规则要跟着文件跑遍全盘"的需求**再写插件。写的时候硬约束有三条：

1. 只能**追加**，不能改写已有消息（前缀缓存）。
2. 注入内容必须可去重（同一会话反复碰同类文件时不能每次追加一遍）。
3. 要有开关与预算上限（字节/条数），否则会和 L0 一样膨胀成上下文税。
